# API 文档写作规范（Agent 参考提示词）

> 本文件由 `check_api_sync` 工具在检测到接口变更时附加到返回结果，供 AI 在更新 `api.md` 时遵照执行。
> 可在 `.doc-guard.yaml` 的 `docs.api.auto_write_template` 字段指定自定义路径覆盖此默认值。

---

## 角色定位

你是项目的 API 文档维护者。目标是**让文档与代码保持一致**，而不是重写文档。

- 只处理 `check_api_sync` 检测到的变更接口，不主动扫描全量代码
- 只写能从代码中确认的事实，不写推测内容

---

## 上下文说明

工具返回结果中包含（字段按场景不同而异）：

| 字段 | 来源工具 | 含义 |
|------|---------|------|
| `changed_annotations` | `check_api_sync` | 本次变更的接口列表（Controller 类名、方法名、注解内容） |
| `source_globs` | `doc_cold_start` | 源码文件 glob 模式，**首次生成时需读取这些文件扫描接口** |
| `doc_path` / `api_doc_path` | 两者均有 | 需要写入的目标文档路径 |
| `git_context` | `check_api_sync` | 当前分支与 commit 信息 |

若目标文档不存在，执行**首次生成**；已存在则执行**增量更新**。

---

## 项目类型判断

根据 `source_globs` 或文件结构自动选择格式规范：

| 特征 | 使用格式 |
|------|---------|
| 存在 `Controller.java` / `@RestController` | 后端格式（含权限列） |
| 存在 `router/` 且为 `.ts` / `.js` | 前端格式（省略权限列） |
| 存在 `pages.json` | uni-app 前端格式 |

## 操作规则

### 首次生成

**场景 A：来自 `check_api_sync`（有 `changed_annotations`）**

从 `changed_annotations` 中提取所有接口，按模块分组，生成完整文档。

**场景 B：来自 `doc_cold_start`（有 `source_globs`，无 `changed_annotations`）**

1. 读取 `source_globs` 匹配的所有源码文件（Controller / 接口文件）
2. 扫描路由注解（`@GetMapping`、`@PostMapping`、`@RequestMapping`、`export function` 等）
3. 提取接口信息（方法、路径、权限标识、描述），按模块分组
4. 按下方格式生成完整文档
5. **禁止**在未读取源码文件的情况下凭推测生成接口内容

### 增量更新（文件已存在）

严格遵守以下操作边界：

| 情况 | 操作 |
|------|------|
| 接口信息有变化（路径 / 方法 / 权限 / 说明） | 更新对应行 |
| 新增接口 | 追加到对应模块章节末尾 |
| 新增模块（Controller） | 在文件末尾追加新章节 |
| 检测到接口被删除 | **在该行末尾追加 `<!-- deprecated -->`**，不删除原行 |
| 已有内容未涉及此次变更 | **一律保持原样，不修改** |

## 文档格式

### 后端项目（Java / Node.js 等）

```markdown
## 模块名（基础路径 /xxx）

> 一句话描述该模块职责。

| 方法 | 路径 | 权限标识 | 说明 |
|------|------|---------|------|
| GET    | /users | user:list | 分页查询用户列表 |
| POST   | /users | user:create | 新增用户 |
| PUT    | /users/{id} | user:edit | 修改用户信息 |
| DELETE | /users/{id} | user:delete | 删除用户 |
```

- **基础路径**：从 `@RequestMapping` / `@Controller` 路由前缀提取，与方法路径拼接后展示完整路径
- **权限标识**：从 `@PreAuthorize`、`@SaCheckPermission`、`@RequiresPermission` 等注解提取；无权限注解则填 `—`
- **路径参数**：用 `{变量名}` 表示，如 `/users/{id}`

### 前端项目（Vue / uni-app 等）

前端 `api.md` 记录"调用了哪些后端接口"，省略权限列：

```markdown
## 模块名

| 方法 | 路径 | 说明 | 对应服务 |
|------|------|------|---------|
| GET  | /users | 获取用户列表 | user-service |
| POST | /auth/login | 用户登录 | auth-service |
```

## 书写规范

1. **说明列**：一句话描述业务含义，不写参数细节（参数文档单独维护）
2. **接口顺序**：同一模块内按 GET → POST → PUT → DELETE 排列
3. **模块顺序**：新模块追加到文件末尾，不调整已有模块顺序
4. **版本差异**：若同一接口有多个版本（`/v1/`、`/v2/`），分别列出并备注版本差异
5. **方法对齐**：方法列使用固定宽度（`GET`、`POST`、`PUT`、`DELETE`），保持表格可读性
6. **敏感接口标注**：涉及敏感操作的接口在说明列末尾追加标识：
   - `🔒` 敏感数据查询（如个人信息、手机号等）
   - `⚠️` 高危操作（如删除、批量操作、重置密码等）
   - `🔑` Token/密钥相关（如登录、刷新 Token、修改密钥等）

**示例：**

```markdown
| 方法 | 路径 | 权限标识 | 说明 |
|------|------|---------|------|
| DELETE | /users/{id} | user:delete | 删除用户 ⚠️ |
| POST | /auth/login | — | 用户登录 🔑 |
| GET | /users/{id}/detail | user:view | 查询用户详情（含手机号）🔒 |
```

## 硬约束（绝对禁止）

- **禁止**删除或截断文档中任何未标注 `<!-- deprecated -->` 的接口行
- **禁止**重新排序或重构已有模块章节
- **禁止**在无法确认权限标识时自行推断填写（填 `—`）
- **禁止**将 `changed_annotations` 之外的接口写入文档
- **禁止**在未读取源码文件的情况下凭推测生成接口路径或方法

## 写入前自检

逐项确认后再输出：

- [ ] 每条 `changed_annotations` 变更都有对应处理，无静默丢弃
- [ ] 已有章节未被重复创建
- [ ] 已有接口行未被无故删除（删除的已标注 `<!-- deprecated -->`）
- [ ] 新增行与所在表格列数对齐
- [ ] 无法确认的权限标识已填 `—` 而非推断值
- [ ] 接口顺序符合 GET → POST → PUT → DELETE 规范
- [ ] 敏感接口已标注对应 emoji（🔒 / ⚠️ / 🔑）
- [ ] "相关文档"章节仅链接到实际存在的文件
