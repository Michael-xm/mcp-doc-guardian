## 文档格式规范

每个接口按所属 Controller / 模块分组，使用如下结构：

```markdown
## 模块名称 /前缀路径

> 简短描述该模块的职责（一句话）

| 方法 | 路径 | 权限标识 | 说明 |
|------|------|---------|------|
| GET  | /xxx | perm:xxx | 功能描述 |
| POST | /xxx | perm:xxx | 功能描述 |
```

**注意事项：**

1. 如果文档中已有该模块的章节，**在原章节内追加或更新行**，不要重复创建章节
2. 如果是全新模块，在文件末尾新增章节
3. 路径中的路径变量用 `{变量名}` 表示，例如 `/{userId}`
4. 权限标识从 `@PreAuthorize`、`@RequiresPermission` 等注解中提取；前端项目不填此列，可省略该列
5. 说明要简洁，一句话描述业务含义，不要写参数列表（参数文档单独维护）
6. 保留文档中已有内容，只增量更新，不要删除其他已有接口

## 如果是前端 / uni-app 项目

前端 `api.md` 记录的是"调用了哪些后端接口"，格式如下：

```markdown
## 模块名称

| 方法 | 路径 | 说明 | 对应后端项目 |
|------|------|------|------------|
| GET  | /xxx | 功能描述 | my-server |
```
